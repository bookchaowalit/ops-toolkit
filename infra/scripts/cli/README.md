# Python Domain CLI

CLI ทุกตัวในโฟลเดอร์นี้มีหน้าที่เป็น interface สำหรับ operational projection
ของ Solo Empire ไม่ใช่ source-ingest boundary ใหม่ กฎและขั้นตอนร่วมอยู่ใน
[Data Lake Workflow for Every App and CLI](../../../learning/platform-engineering/app-cli-data-lake-playbook.md)

## ขั้นตอนร่วมของทุก CLI

```text
input/provider → validate → Object Storage landing → Bronze Parquet
               → Silver/Gold (ถ้าจำเป็น) → SQLite projection → verify
```

ใช้ `ingest.py` สำหรับ batch หรือส่ง event เข้า `se.events` เมื่อเป็น streaming
ที่ต้องการ buffer/replay จากนั้นค่อยเขียนตาราง SQLite ที่ CLI เดิมใช้งานอยู่

`data-intake-cli.py` เป็น control-plane CLI สำหรับลงทะเบียน source และ queue
งาน ingest แบบ lake-first โดยเก็บเฉพาะ policy, idempotency, lease, status และ
lineage ไม่รับ raw payload เอง ดู contract เต็มได้ที่
[`Source Registry and Lake-first Intake Queue`](../../../systems/ai-data/source-registry-and-intake.md)

ห้าม:

- เขียน SQLite ก่อน durable lake write
- เก็บ raw source ไว้แค่ใน SQLite
- ใส่ token/password/cookie ใน payload, metadata, object key หรือ log
- รายงาน success ถ้า manifest, Parquet หรือ checkpoint ยังเขียนไม่สำเร็จ

ตารางข้างต้นเป็น target dataset naming สำหรับการ migrate; CLI ที่ยังเขียน
SQLite โดยตรงต้องถูกย้ายทีละตัว โดยรักษา command/output เดิมไว้ให้ผู้ใช้ก่อน

`decision-cli.py` เป็นข้อยกเว้นของ lake-first ingress เพราะรับเฉพาะคำสั่ง
ควบคุมภายในจากผู้อนุมัติ ไม่รับ raw source payload หรือข้อมูลจาก provider

`seo-cli.py` เก็บหลักฐานลูกค้าไว้ที่ `<book-dev>/github/bookchaowalit-freelance/<client>/seo/` ซึ่งเป็น private
delivery workspace ไม่ใช่ public lake landing และไม่เรียก Search Console /
Ahrefs / GA4 API

Review tasks are generated by `infra/scripts/workflows/decision_review.py`.
Use `--dry-run` to inspect due reviews and `--sync` to create local tasks;
record the result explicitly with `decision-cli.py review`.

## Migration recipe ต่อ CLI

1. ระบุ command ที่สร้างหรือแก้ข้อมูลในตาราง projection
2. สร้าง source record ที่มี stable `id`, `event_time`, payload และ metadata
3. เรียก batch ingest หรือ publish streaming event
4. รอผล durable write และเก็บ `event_id`, `run_id`, manifest/object key
5. ทำ projection ใน transaction เดิม โดยใช้ event ID เป็น idempotency key
6. เพิ่ม `--dry-run`/JSON summary ที่แสดง lake status ก่อน mutation
7. ทดสอบ retry ซ้ำ, malformed input, quarantine และ replay จาก landing
8. อัปเดต learning note/runbook ของ CLI และบันทึก progress ผ่าน `infra/cli.ts`
